# Requirements Document

## Introduction

개인·그룹 알림 서비스는 사용자가 친구 한 명 이상에게 개인 알림을 보내거나 자신이 속한 그룹 하나에 그룹 알림을 보내고, 발송 회차별 확인 현황을 조회하는 웹 서비스다. 알림은 제목과 본문을 나누지 않은 한 문장으로 작성한다. 수신자는 별도 알림 상세 화면이 아니라 받은 알림의 회차별 카드에서 알림을 읽고 확인한다. 앱 진입이나 목록 열람만으로는 응답 상태가 바뀌지 않는다.

알림은 일회성 또는 반복 일정으로 발송할 수 있다. 반복 알림은 회차마다 수신자 목록과 응답 상태를 별도로 기록한다. 그룹 알림의 조회 권한은 현재 그룹 소속 여부와 가장 최근 가입 시점을 기준으로 결정한다. 그룹 구성원의 이메일 공개 설정은 그룹별 멤버십 속성으로 관리한다.

이 문서는 PRD의 1~7절과 확정된 UI 디자인 명세를 요구사항으로 옮긴 것이다. PRD와 UI 디자인 명세가 다른 경우에는 UI 디자인 명세 5장의 변경 사항을 우선한다. PRD 7절 수용 기준은 문서 끝의 "수용 기준 추적표"에서 각 요구사항과 연결한다.

## Glossary

- **알림_서비스**: 이 문서가 정의하는 개인·그룹 알림 웹 애플리케이션 전체.
- **발송_스케줄러**: 알림_서비스 중 일회성_알림과 반복_알림의 발송일을 계산하고 발송_회차를 발송하는 부분.
- **사용자**: Google 로그인을 통해 알림_서비스 계정을 가진 사람.
- **Google_로그인**: Google 계정으로 사용자를 인증하는 알림_서비스의 유일한 가입 및 로그인 방식.
- **로그인_전_요청_경로**: 로그인하지 않은 사람이 인증이 필요한 화면을 요청했을 때 알림_서비스가 보관하는 해당 화면의 경로와 쿼리 정보.
- **닉네임_후보**: 사용자가 입력한 닉네임의 앞뒤 공백을 제거한 값.
- **닉네임**: 다른 사용자에게 표시되는 1자 이상 20자 이하의 닉네임_후보.
- **정규화_이메일**: 입력 이메일 주소의 앞뒤 공백을 제거하고 영문 대소문자를 구분하지 않도록 비교하는 값.
- **기본_이메일_형식**: 앞뒤 공백을 제거한 값에 공백이 없고, `@`가 정확히 하나 있으며, `@` 앞부분이 비어 있지 않고, `@` 뒷부분이 점으로 구분된 두 개 이상의 비어 있지 않은 요소로 구성된 이메일 형식.
- **친구_목록**: 사용자가 정규화_이메일로 추가한 다른 사용자들의 목록. 친구_목록은 소유한 사용자 기준으로 관리된다.
- **친구**: 어떤 사용자의 친구_목록에 들어 있는 다른 사용자.
- **그룹**: 사용자가 생성하고 초대_링크로 구성원을 모으는 사용자 모임.
- **그룹_멤버십**: 한 사용자와 한 그룹의 소속 관계. 가입_시점과 그룹별 이메일_공개_설정을 가진다.
- **그룹_구성원**: 유효한 그룹_멤버십을 가진 사용자.
- **그룹별_이메일_공개_설정**: 해당 그룹의 구성원 목록에서 사용자 이메일 주소를 표시할지 정하는 그룹_멤버십 속성. 값은 '공개' 또는 '비공개'다.
- **초대_링크**: 특정 그룹의 초대 확인 화면으로 연결되는 링크.
- **가입_시점**: 사용자가 그룹을 생성한 시각 또는 그룹 초대를 가장 최근에 수락한 시각.
- **탈퇴_확인**: 그룹 탈퇴 요청을 실행하기 전에 대상 그룹과 탈퇴 결과를 표시하고 사용자에게 실행 또는 취소를 선택하게 하는 단계.
- **탈퇴**: 그룹_구성원이 탈퇴_확인에서 실행을 선택하여 그룹_멤버십을 종료하는 행위.
- **외부_사용자**: 특정 그룹에 대해 현재 그룹_구성원이 아닌 사용자. 초대를 수락하지 않은 사용자와 탈퇴한 사용자를 포함한다.
- **발신자**: 알림을 작성하고 발송한 사용자.
- **알림_문장**: 제목과 본문 구분 없이 작성하고 표시하는 하나의 비어 있지 않은 문자열.
- **알림**: 발신자가 작성한 알림_문장, 발송 대상, 발송 일정을 묶은 단위.
- **발송_방식**: 알림의 대상 지정 방식. '개인_발송' 또는 '그룹_발송' 중 하나다.
- **개인_발송**: 발신자의 친구_목록에서 선택한 한 명 이상의 친구에게 보내는 발송_방식.
- **그룹_발송**: 발신자가 속한 그룹 하나의 구성원 중 발신자를 제외한 전원에게 보내는 발송_방식.
- **수신자**: 특정 발송_회차에서 알림을 받도록 기록된 사용자.
- **일회성_알림**: 발송_회차가 한 번만 생기는 알림.
- **반복_알림**: 반복_주기에 따라 발송_회차가 여러 번 생기는 알림.
- **반복_주기**: 반복_알림의 주기. '매일', '매주', '매월' 중 하나다.
- **주말_제외_옵션**: 반복_알림에서 토요일 또는 일요일로 예정된 발송_회차를 다음 평일로 옮기는 옵션.
- **예정일**: 반복_주기만으로 계산한, 주말_제외_옵션 적용 전의 발송 날짜.
- **발송일**: 예정일에 주말_제외_옵션을 적용한 뒤 실제로 발송_회차를 발송하는 날짜.
- **평일**: 월요일부터 금요일까지의 요일.
- **발송_회차**: 알림이 한 번 발송된 단위. 발송 시각, 수신자 목록, 수신자별 응답_상태와 확인_시각을 가진다.
- **응답_상태**: 한 발송_회차에서 한 수신자의 응답 여부. 값은 '확인' 또는 '미확인'이다.
- **확인_시각**: 수신자가 발송_회차의 확인_버튼을 처음 누른 시각.
- **받은_알림_카드**: 수신자에게 발송_회차 하나를 나타내며 알림_문장, 발송 정보, 본인의 응답_상태와 가능한 동작을 표시하는 목록 항목.
- **확인_버튼**: 수신자가 받은_알림_카드에서 해당 발송_회차에 응답하기 위해 누르는 버튼.
- **응답_현황_버튼**: 사용자가 받은_알림_카드 또는 보낸_알림_카드에서 응답_현황으로 이동하기 위해 누르는 버튼.
- **응답_현황**: 한 알림의 발송_회차 선택기와 선택한 발송_회차의 수신자별 응답_상태 및 확인 집계를 보여주는 화면.
- **발송_회차_선택기**: 응답_현황에서 조회할 발송_회차를 선택하는 목록.
- **보낸_알림_카드**: 발신자가 보낸 알림 하나를 나타내며 알림_문장과 발송 정보를 표시하고 응답_현황으로 연결하는 목록 항목.
- **주요_목록**: 친구_목록, 그룹 목록, 받은 알림 목록, 보낸 알림 목록.
- **빈_상태_안내**: 주요_목록에 표시할 항목이 없을 때 항목이 없다는 사실과 가능한 다음 행동을 설명하는 안내.

## Requirements

### Requirement 1: Google 계정 인증과 프로필

**User Story:** As a 사용자, I want Google 계정으로 가입하고 로그인하며 프로필을 관리하고 싶다, so that 별도 비밀번호 없이 알림_서비스를 이용할 수 있다.

#### Acceptance Criteria

1. THE 알림_서비스 SHALL Google_로그인을 유일한 계정 생성 방식과 로그인 방식으로 제공한다.
2. WHEN 계정이 없는 사람이 Google_로그인을 완료하면, THE 알림_서비스 SHALL 해당 Google 계정의 정규화_이메일로 새 사용자 계정을 생성한다.
3. WHEN 새 사용자 계정이 생성되면, THE 알림_서비스 SHALL Google 프로필 이름의 앞뒤 공백을 제거한 값을 초기 닉네임으로 설정한다.
4. IF Google 프로필 이름의 앞뒤 공백을 제거한 값이 1자 이상 20자 이하가 아니면, THEN THE 알림_서비스 SHALL 사용자에게 유효한 닉네임 저장을 요청한다.
5. WHEN 계정이 있는 사용자가 Google_로그인을 완료하면, THE 알림_서비스 SHALL 해당 사용자의 기존 계정으로 로그인 상태를 만든다.
6. IF Google_로그인이 실패하거나 취소되면, THEN THE 알림_서비스 SHALL 계정을 생성하지 않고 로그인 실패 메시지를 표시한다.
7. WHEN 로그인하지 않은 사람이 인증이 필요한 경로를 요청하면, THE 알림_서비스 SHALL 로그인_전_요청_경로를 보관하고 Google_로그인 화면을 표시한다.
8. WHEN 로그인_전_요청_경로가 있는 사람이 Google_로그인을 완료하면, THE 알림_서비스 SHALL 해당 사람을 로그인_전_요청_경로로 이동시킨다.
9. WHEN 사용자가 닉네임_후보를 저장하면, THE 알림_서비스 SHALL 닉네임_후보의 길이를 검증한다.
10. WHEN 닉네임_후보가 1자 이상 20자 이하이면, THE 알림_서비스 SHALL 해당 사용자의 닉네임을 닉네임_후보로 갱신한다.
11. IF 닉네임_후보가 비어 있거나 20자를 초과하면, THEN THE 알림_서비스 SHALL 기존 닉네임을 유지하고 1자 이상 20자 이하 입력을 요청하는 오류 메시지를 표시한다.
12. WHEN 로그인한 사용자가 로그아웃을 요청하면, THE 알림_서비스 SHALL 로그인 상태를 종료하고 Google_로그인 화면을 표시한다.
13. WHILE 사용자가 로그아웃 상태이면, THE 알림_서비스 SHALL 인증이 필요한 화면과 사용자 데이터를 표시하지 않는다.

### Requirement 2: 이메일 기반 친구 추가와 목록

**User Story:** As a 사용자, I want 이메일 주소로 다른 사용자를 친구로 추가하고 싶다, so that 친구에게 개인_발송 알림을 보낼 수 있다.

#### Acceptance Criteria

1. WHEN 사용자가 친구 추가를 요청하면, THE 알림_서비스 SHALL 입력 이메일 주소가 기본_이메일_형식인지 검증한다.
2. IF 친구 추가 요청의 이메일 주소가 기본_이메일_형식이 아니면, THEN THE 알림_서비스 SHALL 친구_목록을 유지하고 유효한 이메일 주소 입력을 요청하는 오류 메시지를 표시한다.
3. WHEN 사용자가 가입된 다른 사용자의 이메일 주소를 기본_이메일_형식으로 입력하면, THE 알림_서비스 SHALL 영문 대소문자를 구분하지 않는 정규화_이메일로 해당 다른 사용자를 찾는다.
4. WHEN 정규화_이메일에 해당하는 다른 사용자가 존재하면, THE 알림_서비스 SHALL 해당 다른 사용자를 요청한 사용자의 친구_목록에 추가한다.
5. IF 정규화_이메일에 해당하는 가입 사용자가 없으면, THEN THE 알림_서비스 SHALL 친구_목록을 유지하고 사용자를 찾을 수 없다는 메시지를 표시한다.
6. IF 사용자가 본인의 정규화_이메일로 친구 추가를 요청하면, THEN THE 알림_서비스 SHALL 친구_목록을 유지하고 본인은 친구로 추가할 수 없다는 메시지를 표시한다.
7. IF 사용자가 이미 친구_목록에 있는 사용자의 정규화_이메일로 친구 추가를 요청하면, THEN THE 알림_서비스 SHALL 친구_목록을 유지하고 이미 친구라는 메시지를 표시한다.
8. THE 알림_서비스 SHALL 한 사용자의 친구_목록에 같은 친구를 한 번만 포함한다.
9. WHEN 사용자가 친구_목록을 요청하면, THE 알림_서비스 SHALL 각 친구의 닉네임과 이메일 주소를 표시한다.
10. WHEN 사용자의 친구_목록에 친구가 없으면, THE 알림_서비스 SHALL 친구가 없다는 빈_상태_안내와 이메일로 친구를 추가하는 다음 행동을 표시한다.

### Requirement 3: 그룹 생성과 초대 링크

**User Story:** As a 사용자, I want 그룹을 만들고 초대 링크로 다른 사용자를 초대하고 싶다, so that 친구가 아닌 사람도 그룹에 모아 함께 알림을 주고받을 수 있다.

#### Acceptance Criteria

1. WHEN 사용자가 비어 있지 않은 그룹 이름으로 그룹 생성을 요청하면, THE 알림_서비스 SHALL 그룹을 생성하고 요청한 사용자의 그룹_멤버십을 등록한다.
2. WHEN 그룹 생성자의 그룹_멤버십이 등록되면, THE 알림_서비스 SHALL 생성 시각을 가입_시점으로 기록한다.
3. WHEN 그룹 생성자의 그룹_멤버십이 등록되면, THE 알림_서비스 SHALL 해당 그룹의 그룹별_이메일_공개_설정을 '비공개'로 설정한다.
4. IF 그룹 생성 요청의 그룹 이름이 비어 있거나 공백으로만 이루어져 있으면, THEN THE 알림_서비스 SHALL 그룹을 생성하지 않고 그룹 이름 입력 오류 메시지를 표시한다.
5. WHEN 그룹_구성원이 해당 그룹의 초대_링크를 요청하면, THE 알림_서비스 SHALL 해당 그룹의 초대_링크를 제공한다.
6. WHEN 그룹_구성원이 초대_링크 복사를 요청하면, THE 알림_서비스 SHALL 해당 그룹의 초대_링크를 복사 대상으로 제공하고 복사 완료 메시지를 표시한다.
7. IF 초대_링크 복사가 완료되지 않으면, THEN THE 알림_서비스 SHALL 복사 실패 메시지와 다시 복사하는 동작을 표시한다.
8. IF 외부_사용자가 그룹의 초대_링크 발급을 요청하면, THEN THE 알림_서비스 SHALL 초대_링크를 제공하지 않고 권한 없음 메시지를 표시한다.
9. WHEN 사용자가 속한 그룹이 없으면, THE 알림_서비스 SHALL 그룹이 없다는 빈_상태_안내와 새 그룹을 만드는 다음 행동을 표시한다.

### Requirement 4: 초대 확인과 수락

**User Story:** As a 초대받은 사용자, I want 초대 링크를 열어 초대 내용을 확인한 뒤 수락하고 싶다, so that 내가 선택한 경우에만 그룹_구성원이 된다.

#### Acceptance Criteria

1. WHEN 로그인한 사용자가 유효한 초대_링크를 열면, THE 알림_서비스 SHALL 그룹 이름과 초대 수락 동작이 있는 초대 확인 화면을 표시한다.
2. WHEN 로그인하지 않은 사람이 유효한 초대_링크를 열면, THE 알림_서비스 SHALL 해당 초대 확인 화면을 로그인_전_요청_경로로 보관하고 Google_로그인을 요청한다.
3. WHILE 초대_링크를 연 사용자가 초대를 수락하지 않은 상태이면, THE 알림_서비스 SHALL 해당 사용자를 해당 그룹의 외부_사용자로 처리한다.
4. WHEN 사용자가 초대 확인 화면에서 초대를 수락하면, THE 알림_서비스 SHALL 친구 관계 여부와 관계없이 해당 사용자의 그룹_멤버십을 등록한다.
5. WHEN 사용자가 초대를 처음 수락하거나 탈퇴 후 다시 수락하면, THE 알림_서비스 SHALL 수락 시각을 해당 그룹_멤버십의 가입_시점으로 기록한다.
6. WHEN 사용자가 초대를 처음 수락하거나 탈퇴 후 다시 수락하면, THE 알림_서비스 SHALL 해당 그룹의 그룹별_이메일_공개_설정을 '비공개'로 설정한다.
7. IF 이미 그룹_구성원인 사용자가 해당 그룹의 초대_링크를 열면, THEN THE 알림_서비스 SHALL 이미 구성원이라는 안내를 표시하고 기존 가입_시점과 그룹별_이메일_공개_설정을 유지한다.
8. IF 사용자가 존재하지 않는 그룹을 가리키거나 형식이 잘못된 초대_링크를 열면, THEN THE 알림_서비스 SHALL 유효하지 않은 초대라는 메시지를 표시하고 그룹 정보를 표시하지 않는다.

### Requirement 5: 그룹 탈퇴

**User Story:** As a 그룹_구성원, I want 탈퇴 결과를 확인한 뒤 그룹에서 탈퇴하고 싶다, so that 실수로 탈퇴하지 않으면서 더 이상 해당 그룹의 알림을 받지 않을 수 있다.

#### Acceptance Criteria

1. WHEN 그룹_구성원이 그룹 탈퇴를 요청하면, THE 알림_서비스 SHALL 대상 그룹과 탈퇴 후 그룹 알림 및 응답 현황 조회 권한이 제거된다는 내용을 담은 탈퇴_확인을 표시한다.
2. WHEN 그룹_구성원이 탈퇴_확인에서 취소를 선택하면, THE 알림_서비스 SHALL 해당 그룹_멤버십을 유지한다.
3. WHEN 그룹_구성원이 탈퇴_확인에서 실행을 선택하면, THE 알림_서비스 SHALL 해당 사용자의 그룹_멤버십을 종료한다.
4. WHEN 사용자의 그룹_멤버십이 종료되면, THE 알림_서비스 SHALL 종료 시점 이후 해당 사용자를 해당 그룹의 외부_사용자로 처리한다.

### Requirement 6: 그룹 구성원 목록과 그룹별 이메일 공개

**User Story:** As a 그룹_구성원, I want 그룹 구성원 목록을 보고 각 그룹에서 내 이메일 공개 여부를 정하고 싶다, so that 그룹별로 이메일 노출을 통제할 수 있다.

#### Acceptance Criteria

1. WHEN 그룹_구성원이 그룹 구성원 목록을 요청하면, THE 알림_서비스 SHALL 해당 그룹의 모든 그룹_구성원을 닉네임과 함께 표시한다.
2. WHILE 그룹_구성원의 해당 그룹 그룹별_이메일_공개_설정이 '공개'이면, THE 알림_서비스 SHALL 해당 그룹의 구성원 목록에 해당 그룹_구성원의 이메일 주소를 표시한다.
3. WHILE 그룹_구성원의 해당 그룹 그룹별_이메일_공개_설정이 '비공개'이면, THE 알림_서비스 SHALL 해당 그룹의 구성원 목록에 해당 그룹_구성원의 닉네임만 표시한다.
4. WHEN 그룹_구성원이 그룹 상세에서 그룹별_이메일_공개_설정을 변경하면, THE 알림_서비스 SHALL 선택한 그룹의 그룹_멤버십에만 변경값을 저장한다.
5. WHEN 한 그룹의 그룹별_이메일_공개_설정이 변경되면, THE 알림_서비스 SHALL 해당 사용자가 속한 다른 그룹의 그룹별_이메일_공개_설정을 유지한다.
6. IF 외부_사용자가 그룹 구성원 목록을 요청하면, THEN THE 알림_서비스 SHALL 구성원 목록을 표시하지 않고 권한 없음 메시지를 표시한다.

### Requirement 7: 알림 문장과 발송 방식 선택

**User Story:** As a 발신자, I want 한 문장 알림마다 개인 발송과 그룹 발송 중 하나를 고르고 싶다, so that 알림 내용과 수신 대상이 명확하게 정해진다.

#### Acceptance Criteria

1. WHEN 발신자가 알림 작성을 시작하면, THE 알림_서비스 SHALL 제목과 본문으로 분리되지 않은 알림_문장 입력 하나를 제공한다.
2. WHEN 발신자가 알림 작성을 시작하면, THE 알림_서비스 SHALL 개인_발송과 그룹_발송 중 하나를 발송_방식으로 선택하도록 요청한다.
3. THE 알림_서비스 SHALL 각 알림에 개인_발송 수신 대상과 그룹_발송 대상 중 한 종류만 저장한다.
4. IF 발신자가 개인 수신자와 그룹을 함께 지정해 발송을 요청하면, THEN THE 알림_서비스 SHALL 해당 알림을 발송하지 않고 개인과 그룹을 함께 지정할 수 없다는 메시지를 표시한다.
5. IF 발신자가 입력한 알림_문장이 비어 있거나 공백으로만 이루어져 있으면, THEN THE 알림_서비스 SHALL 해당 알림을 발송하지 않고 알림 문장 입력 오류 메시지를 표시한다.

### Requirement 8: 개인 발송

**User Story:** As a 발신자, I want 내 친구 목록에서 한 명 이상을 골라 알림을 보내고 싶다, so that 원하는 사람에게만 알림을 보낼 수 있다.

#### Acceptance Criteria

1. WHILE 발신자가 개인_발송을 선택한 상태이면, THE 알림_서비스 SHALL 발신자의 친구_목록에 있는 사용자만 선택 가능한 수신 대상으로 표시한다.
2. WHEN 발신자가 친구 한 명 이상을 선택한 개인_발송 알림의 발송_회차가 발송되면, THE 알림_서비스 SHALL 발신자가 선택한 각 친구를 해당 발송_회차의 수신자로 기록한다.
3. IF 개인_발송 요청에 발신자의 친구_목록에 없는 사용자가 포함되어 있으면, THEN THE 알림_서비스 SHALL 해당 알림을 발송하지 않고 친구가 아닌 사용자는 선택할 수 없다는 메시지를 표시한다.
4. IF 발신자가 수신 대상을 한 명도 선택하지 않고 개인_발송을 요청하면, THEN THE 알림_서비스 SHALL 해당 알림을 발송하지 않고 수신 대상을 선택하라는 메시지를 표시한다.

### Requirement 9: 그룹 발송

**User Story:** As a 그룹_구성원, I want 내가 속한 그룹 하나를 골라 구성원 전체에게 알림을 보내고 싶다, so that 친구가 아닌 구성원에게도 한 번에 알릴 수 있다.

#### Acceptance Criteria

1. WHILE 발신자가 그룹_발송을 선택한 상태이면, THE 알림_서비스 SHALL 발신자가 그룹_구성원으로 속한 그룹만 선택 가능한 대상으로 표시한다.
2. WHILE 발신자가 그룹_발송을 선택한 상태이면, THE 알림_서비스 SHALL 한 알림에 그룹을 하나만 선택할 수 있게 한다.
3. IF 그룹_발송 요청에 두 개 이상의 그룹이 지정되어 있으면, THEN THE 알림_서비스 SHALL 해당 알림을 발송하지 않고 그룹은 하나만 지정할 수 있다는 메시지를 표시한다.
4. THE 알림_서비스 SHALL 모든 그룹_구성원이 자신이 속한 그룹에 그룹_발송 알림을 등록할 수 있게 한다.
5. IF 외부_사용자가 해당 그룹으로 그룹_발송을 요청하면, THEN THE 알림_서비스 SHALL 해당 알림을 발송하지 않고 권한 없음 메시지를 표시한다.
6. WHEN 그룹_발송 알림의 발송_회차가 발송되면, THE 알림_서비스 SHALL 발송 시점의 그룹_구성원 중 발신자를 제외한 전원을 해당 발송_회차의 수신자로 기록한다.
7. IF 반복 그룹_발송 알림의 발송일에 발신자가 해당 그룹의 외부_사용자이면, THEN THE 발송_스케줄러 SHALL 해당 발송_회차를 발송하지 않는다.
8. IF 그룹_발송 알림의 발송 시점에 발신자를 제외한 그룹_구성원이 없으면, THEN THE 발송_스케줄러 SHALL 해당 발송_회차를 발송하지 않는다.
9. THE 알림_서비스 SHALL 각 그룹_발송 발송_회차의 수신자 집합을 발송 시점의 그룹_구성원 집합에서 발신자를 제외한 집합과 같게 기록한다.

### Requirement 10: 일회성 알림과 반복 알림 일정

**User Story:** As a 발신자, I want 알림을 한 번만 보내거나 매일·매주·매월 반복해 보내고 싶다, so that 정기적으로 확인이 필요한 일을 매번 다시 작성하지 않아도 된다.

#### Acceptance Criteria

1. WHEN 발신자가 일회성_알림을 등록하면, THE 발송_스케줄러 SHALL 발신자가 지정한 발송 일시에 발송_회차를 한 번 발송한다.
2. THE 알림_서비스 SHALL 반복_알림의 반복_주기로 '매일', '매주', '매월'을 제공한다.
3. WHERE 반복_주기가 '매일'이면, THE 발송_스케줄러 SHALL 반복 시작일부터 매일을 예정일로 정한다.
4. WHERE 반복_주기가 '매주'이면, THE 발송_스케줄러 SHALL 반복 시작일 이후 발신자가 지정한 요일을 매주 예정일로 정한다.
5. WHERE 반복_주기가 '매월'이면, THE 발송_스케줄러 SHALL 반복 시작일 이후 발신자가 지정한 일자를 매월 예정일로 정한다.
6. WHERE 반복_주기가 '매월'이고 해당 월에 지정한 일자가 없으면, THE 발송_스케줄러 SHALL 해당 월의 마지막 날을 예정일로 정한다.
7. THE 알림_서비스 SHALL 세 반복_주기 모두에서 주말_제외_옵션을 선택할 수 있게 한다.
8. WHERE 주말_제외_옵션이 꺼져 있으면, THE 발송_스케줄러 SHALL 각 예정일을 발송일로 정한다.
9. WHERE 주말_제외_옵션이 켜져 있고 예정일이 토요일 또는 일요일이면, THE 발송_스케줄러 SHALL 해당 예정일 다음의 첫 평일을 발송일로 정한다.
10. WHERE 주말_제외_옵션이 켜져 있고 예정일이 평일이면, THE 발송_스케줄러 SHALL 해당 예정일을 발송일로 정한다.
11. WHERE 주말_제외_옵션이 켜져 있고 옮겨진 발송일이 같은 알림의 다른 발송일과 같으면, THE 발송_스케줄러 SHALL 해당 날짜에 발송_회차를 하나만 발송한다.
12. WHERE 주말_제외_옵션이 켜져 있으면, THE 발송_스케줄러 SHALL 각 발송일을 대응하는 예정일과 같거나 이후인 첫 평일로 계산한다.
13. THE 발송_스케줄러 SHALL 예정일, 발송일, 요일을 한국 표준시인 Asia/Seoul 기준으로 계산한다.
14. WHEN 발신자가 반복_알림의 중지를 요청하면, THE 발송_스케줄러 SHALL 중지 요청 이후의 발송_회차 생성을 중단한다.
15. WHEN 반복_알림이 중지되면, THE 알림_서비스 SHALL 중지 전에 발송된 발송_회차 기록을 유지한다.

### Requirement 11: 발송 회차별 기록

**User Story:** As a 발신자, I want 반복 알림의 응답을 회차마다 따로 보고 싶다, so that 현재 회차의 확인 현황이 다른 회차와 섞이지 않는다.

#### Acceptance Criteria

1. WHEN 발송_회차가 발송되면, THE 알림_서비스 SHALL 해당 발송_회차의 발송 시각, 수신자 목록, 수신자별 응답_상태와 확인_시각을 다른 발송_회차와 별도로 기록한다.
2. WHEN 새 발송_회차가 발송되면, THE 알림_서비스 SHALL 해당 발송_회차의 모든 수신자 응답_상태를 '미확인'으로 설정한다.
3. WHEN 새 발송_회차가 발송되면, THE 알림_서비스 SHALL 해당 발송_회차의 모든 수신자 확인_시각을 빈 값으로 설정한다.
4. WHEN 수신자의 응답_상태가 한 발송_회차에서 '확인'으로 바뀌면, THE 알림_서비스 SHALL 같은 알림의 다른 발송_회차에 기록된 응답_상태와 확인_시각을 유지한다.
5. WHEN 발송_회차가 발송된 뒤 그룹_구성원이 바뀌면, THE 알림_서비스 SHALL 이미 발송된 발송_회차의 수신자 목록을 발송 시점의 목록으로 유지한다.

### Requirement 12: 받은 알림의 회차별 카드

**User Story:** As a 수신자, I want 발송 회차별 카드에서 알림을 읽고 내 확인 상태를 처리하고 싶다, so that 별도 상세 화면 없이 각 회차에 응답할 수 있다.

#### Acceptance Criteria

1. WHEN 발송_회차가 발송되면, THE 알림_서비스 SHALL 해당 발송_회차의 각 수신자에게 받은_알림_카드 한 개를 표시한다.
2. THE 알림_서비스 SHALL 받은_알림_카드를 알림_문장을 읽고 확인 응답을 수행하는 유일한 알림 열람 화면으로 제공한다.
3. WHEN 같은 알림의 발송_회차가 두 개 이상 존재하면, THE 알림_서비스 SHALL 각 발송_회차를 서로 다른 받은_알림_카드로 표시한다.
4. THE 알림_서비스 SHALL 각 받은_알림_카드에 알림_문장, 발신자, 발송_방식, 발송_회차와 발송 시각을 표시한다.
5. THE 알림_서비스 SHALL 각 받은_알림_카드에 현재 사용자의 해당 발송_회차 응답_상태를 표시한다.
6. WHILE 개인_발송 수신자의 응답_상태가 '미확인'이면, THE 알림_서비스 SHALL 해당 받은_알림_카드의 동작을 확인_버튼 하나로 구성한다.
7. WHILE 개인_발송 수신자의 응답_상태가 '확인'이면, THE 알림_서비스 SHALL 해당 받은_알림_카드에 확인_시각을 표시한다.
8. WHILE 그룹_발송 수신자의 응답_상태가 '미확인'이면, THE 알림_서비스 SHALL 해당 받은_알림_카드에 확인_버튼과 응답_현황_버튼을 표시한다.
9. WHILE 그룹_발송 수신자의 응답_상태가 '확인'이면, THE 알림_서비스 SHALL 해당 받은_알림_카드에 확인_시각과 응답_현황_버튼을 표시한다.
10. WHEN 수신자에게 표시할 받은_알림_카드가 없으면, THE 알림_서비스 SHALL 받은 알림이 없다는 빈_상태_안내와 새 알림을 작성하는 다음 행동을 표시한다.
11. WHILE 사용자가 그룹의 외부_사용자이면, THE 알림_서비스 SHALL 받은 알림 목록에서 해당 그룹의 그룹_발송 받은_알림_카드를 제외한다.

### Requirement 13: 확인 응답

**User Story:** As a 수신자, I want 받은 알림 카드의 확인 버튼으로 응답하고 싶다, so that 발신자가 확인 사실과 확인 시각을 알 수 있다.

#### Acceptance Criteria

1. WHILE 수신자가 확인_버튼을 누르지 않은 상태이면, THE 알림_서비스 SHALL 앱 진입, 받은 알림 목록 표시, 받은_알림_카드 표시 후에도 해당 발송_회차의 응답_상태를 '미확인'으로 유지한다.
2. WHEN 수신자가 받은_알림_카드의 확인_버튼을 처음 누르면, THE 알림_서비스 SHALL 해당 발송_회차에서 해당 수신자의 응답_상태를 '확인'으로 바꾼다.
3. WHEN 수신자가 받은_알림_카드의 확인_버튼을 처음 누르면, THE 알림_서비스 SHALL 요청 처리 시각을 해당 수신자의 확인_시각으로 기록한다.
4. WHEN 응답_상태가 이미 '확인'인 수신자가 같은 발송_회차의 확인 응답을 다시 요청하면, THE 알림_서비스 SHALL 해당 응답_상태와 최초 확인_시각을 유지한다.
5. IF 해당 발송_회차의 수신자가 아닌 사용자가 확인 응답을 요청하면, THEN THE 알림_서비스 SHALL 요청을 거부하고 해당 발송_회차의 모든 응답_상태와 확인_시각을 유지한다.
6. IF 그룹에서 탈퇴한 사용자가 해당 그룹의 그룹_발송 발송_회차에 확인 응답을 요청하면, THEN THE 알림_서비스 SHALL 요청을 거부하고 해당 발송_회차의 모든 응답_상태와 확인_시각을 유지한다.

### Requirement 14: 응답 현황의 회차별 표시

**User Story:** As a 응답 현황 조회 사용자, I want 회차를 선택하고 회차별 확인 집계를 보고 싶다, so that 각 발송 회차의 진행 상황을 구분할 수 있다.

#### Acceptance Criteria

1. WHEN 사용자가 응답_현황을 열면, THE 알림_서비스 SHALL 해당 알림의 발송_회차_선택기를 표시한다.
2. WHEN 사용자가 조회 가능한 발송_회차를 선택하면, THE 알림_서비스 SHALL 선택한 발송_회차의 확인 수와 전체 수신자 수를 표시한다.
3. WHEN 사용자가 조회 가능한 발송_회차를 선택하면, THE 알림_서비스 SHALL 선택한 발송_회차의 수신자별 응답_상태를 표시한다.
4. WHILE 수신자의 응답_상태가 '확인'이면, THE 알림_서비스 SHALL 응답_현황의 해당 수신자 항목에 확인_시각을 표시한다.
5. WHILE 수신자의 응답_상태가 '미확인'이면, THE 알림_서비스 SHALL 응답_현황의 해당 수신자 항목에 '미확인' 상태를 표시한다.
6. THE 알림_서비스 SHALL 선택한 발송_회차의 확인 수를 응답_상태가 '확인'인 수신자 수와 같게 표시한다.
7. THE 알림_서비스 SHALL 선택한 발송_회차의 전체 수신자 수를 해당 발송_회차에 기록된 수신자 수와 같게 표시한다.

### Requirement 15: 개인 발송 응답 현황 조회 권한

**User Story:** As a 개인_발송의 발신자, I want 내가 고른 수신자 각각의 확인 여부를 보고 싶다, so that 누구에게 다시 연락해야 하는지 알 수 있다.

#### Acceptance Criteria

1. WHEN 개인_발송 알림의 발신자가 응답_현황을 요청하면, THE 알림_서비스 SHALL 조회할 발송_회차의 모든 수신자 닉네임, 응답_상태와 확인_시각을 표시한다.
2. WHEN 개인_발송 알림의 수신자가 응답_현황 경로를 직접 요청하면, THE 알림_서비스 SHALL 해당 수신자가 수신자로 기록된 발송_회차의 본인 응답_상태와 확인_시각만 표시한다.
3. IF 개인_발송 알림의 발신자도 수신자도 아닌 사용자가 해당 알림 또는 응답_현황을 요청하면, THEN THE 알림_서비스 SHALL 알림_문장과 응답_현황을 표시하지 않고 권한 없음 메시지를 표시한다.

### Requirement 16: 그룹 발송 응답 현황 조회 권한

**User Story:** As a 그룹_구성원, I want 가장 최근 가입 이후 그룹에 발송된 회차의 응답 현황을 보고 싶다, so that 현재 가입 기간에 공유된 확인 현황을 파악할 수 있다.

#### Acceptance Criteria

1. WHEN 그룹_구성원이 그룹_발송 알림의 응답_현황을 요청하면, THE 알림_서비스 SHALL 해당 그룹_구성원의 가입_시점과 같거나 이후에 발송된 발송_회차를 조회 가능하게 표시한다.
2. WHEN 그룹_구성원이 그룹_발송 알림의 응답_현황을 요청하면, THE 알림_서비스 SHALL 해당 그룹_구성원의 가입_시점 이전에 발송된 발송_회차를 발송_회차_선택기에 비활성 상태와 '조회 불가' 문구로 표시한다.
3. WHEN 그룹_구성원이 조회 가능한 발송_회차를 선택하면, THE 알림_서비스 SHALL 해당 발송_회차의 모든 수신자 닉네임, 응답_상태와 확인_시각을 표시한다.
4. THE 알림_서비스 SHALL 그룹_발송 알림의 발신자에게 다른 그룹_구성원과 같은 가입_시점 기반 조회 범위를 적용한다.
5. IF 그룹_구성원이 가입_시점 이전 발송_회차를 직접 요청하면, THEN THE 알림_서비스 SHALL 해당 발송_회차의 수신자와 응답 정보를 표시하지 않고 '조회 불가' 메시지를 표시한다.
6. IF 외부_사용자가 그룹_발송 알림 또는 응답_현황 경로를 직접 요청하면, THEN THE 알림_서비스 SHALL 알림_문장과 응답_현황을 표시하지 않고 '조회 권한 없음' 메시지를 표시한다.
7. WHEN 그룹_구성원이 그룹에서 탈퇴하면, THE 알림_서비스 SHALL 탈퇴 처리 시점부터 해당 사용자의 해당 그룹 모든 그룹_발송 알림과 응답_현황 조회 권한을 제거한다.
8. WHEN 그룹_구성원이 그룹에서 탈퇴하면, THE 알림_서비스 SHALL 해당 사용자가 과거에 보내거나 받은 해당 그룹의 그룹_발송 알림에도 탈퇴 후 조회 권한 제거를 적용한다.
9. THE 알림_서비스 SHALL 사용자가 현재 그룹_구성원이고 발송_회차의 발송 시각이 해당 사용자의 가장 최근 가입_시점과 같거나 이후인 경우에만 해당 그룹_발송 발송_회차의 수신자와 응답 정보를 표시한다.

### Requirement 17: 보낸 알림 목록

**User Story:** As a 발신자, I want 내가 보낸 알림 목록에서 알림을 선택하고 응답 현황으로 이동하고 싶다, so that 발송한 알림의 확인 진행 상황을 찾을 수 있다.

#### Acceptance Criteria

1. WHEN 사용자가 보낸 알림 목록을 요청하면, THE 알림_서비스 SHALL 해당 사용자가 발신자인 알림마다 보낸_알림_카드 한 개를 표시한다.
2. THE 알림_서비스 SHALL 각 보낸_알림_카드에 알림_문장, 발송_방식과 발송 일정 정보를 표시한다.
3. WHEN 사용자가 보낸_알림_카드를 선택하면, THE 알림_서비스 SHALL 해당 알림의 응답_현황을 표시한다.
4. WHILE 사용자가 그룹의 외부_사용자이면, THE 알림_서비스 SHALL 보낸 알림 목록에서 해당 그룹의 그룹_발송 보낸_알림_카드를 제외한다.
5. WHEN 사용자에게 표시할 보낸_알림_카드가 없으면, THE 알림_서비스 SHALL 보낸 알림이 없다는 빈_상태_안내와 새 알림을 작성하는 다음 행동을 표시한다.

## 가정 및 미결 사항

1. 모든 예정일, 발송일과 요일은 한국 표준시인 Asia/Seoul 기준이다 (10.13).
2. 주말_제외_옵션은 토요일과 일요일만 옮기며 공휴일은 고려하지 않는다.
3. 매월 반복에서 지정한 일자가 해당 월에 없으면 해당 월의 마지막 날에 발송한다 (10.6).
4. '매일' 반복에 주말_제외_옵션을 적용해 여러 예정일이 같은 평일로 이동하면 해당 날짜에는 한 회차만 발송한다 (10.11).
5. 반복_알림 중지 기능은 종료일이 없는 반복을 멈추기 위해 포함한다. 종료일 지정과 알림 수정·삭제는 현재 범위에 포함하지 않는다.
6. 발신자가 그룹에서 탈퇴하면 해당 발신자의 반복 그룹_발송 알림은 이후 회차를 발송하지 않는다 (9.7). 발신자 외 구성원이 없을 때도 회차를 발송하지 않는다 (9.8).
7. 친구 추가는 상대방 수락 없이 요청한 사용자의 친구_목록에만 추가되는 단방향 관계로 가정한다. 친구 요청 승인과 친구 삭제는 현재 범위에 포함하지 않는다.
8. 친구 추가 실패 메시지는 입력 이메일 주소에 해당하는 가입 사용자 존재 여부를 드러낼 수 있다 (2.5). 개인정보 노출을 줄이는 통합 오류 메시지 정책은 추후 결정이 필요하다.
9. 초대_링크는 해당 그룹의 모든 그룹_구성원이 발급할 수 있고 만료되지 않는 것으로 가정한다. 링크 폐기와 재발급은 현재 범위에 포함하지 않는다.
10. 재가입 시 가입_시점과 그룹별_이메일_공개_설정은 새 그룹_멤버십 기준으로 초기화된다 (4.5, 4.6). 이전 가입 기간의 발송_회차는 재가입 후에도 조회할 수 없다 (16.2, 16.9).
11. 알림 전달은 앱 내 받은 알림 목록으로 한정한다. 모바일 푸시와 이메일 알림은 현재 범위에 포함하지 않는다.
12. 닉네임 검증에서 제거하는 공백은 입력값 앞뒤의 공백이다. 닉네임 내부 공백은 문자 수에 포함하여 허용한다 (1.9~1.11).
13. 기본_이메일_형식은 서비스 입력 검증 기준이며 모든 국제 이메일 주소 형식을 포괄하지 않는다. 계정과 친구 비교에서는 정규화_이메일을 사용한다 (1.2, 2.3).
14. 보낸 알림 목록은 알림마다 카드 한 개를 표시하고, 회차 구분은 카드를 선택한 뒤 응답_현황의 발송_회차_선택기에서 제공한다 (17.1, 14.1).
